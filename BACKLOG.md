# ZeroSeek — Бэклог

Фичи и задачи, которые запланированы или необходимы, но пока не реализованы.

## Высокий приоритет

### 1. Автоопределение C2ME
**Что:** При старте сервера обнаруживать мод C2ME и автоматически отключать `mmapEnabled`, если он загружен.  
**Почему:** C2ME заменяет систему чанков и конфликтует с MMap/Delta Layer ZeroSeek.  
**Где:** `ZeroSeekMod.onInitializeServer()` — проверка `FabricLoader.getInstance().isModLoaded("c2me")`.  
**Сложность:** низкая. Высокий выигрыш в стабильности.

### 2. Async Generation Wrapper (использование loader pool)
**Что:** Задействовать уже созданный `AsyncChunkService.loaderPool` для асинхронной работы.  
**Варианты:**
- (A) **Async MMap prefetch pipeline** — предварительная загрузка `.mca` для предсказанных чанков.
- (B) **Полный async generation wrapper** — делегировать vanilla `ChunkStatus` pipeline в loader pool и возвращать placeholder-чанк во время генерации.
**Почему:** Сейчас loader pool создаётся, но не используется. Вариант (A) — самый безопасный первый шаг.  
**Сложность:** средняя.

## Средний приоритет

### 3. TeleportGate
**Что:** Ленивые телепорты, которые откладывают применение `ServerPlayer.teleport()` / `changeDimension()` до готовности целевого региона.  
**Почему:** Предотвращает резкие просадки TPS при телепортации или смене измерения.  
**Где:** Новый пакет `teleport/` + `mixin/ServerPlayerMixin.java`.  
**Ссылка на план:** IMPLEMENTATION_PLAN 3.4.4.  
**Сложность:** средняя.

### 4. SpeedCap
**Что:** Ограничение скорости сущностей при CRITICAL TPS (элитры, лошади, свиньи, вагонетки и т.д.).  
**Почему:** Не даёт игрокам убежать от прогруженной зоны во время стресса сервера.  
**Где:** `mixin/LivingEntityMixin.java` или обработка пакетов движения.  
**Ссылка на план:** IMPLEMENTATION_PLAN 3.4.6.  
**Сложность:** низкая-средняя.

### 5. TPS Hysteresis / Recovery Delay
**Что:** Добавить задержку/гистерезис перед переключением состояний TPS governor и перед восстановлением из STRESS/CRITICAL в NORMAL.  
**Почему:** Избежать быстрого дёрганья `simulation-distance`, заморозки тикетов и throttle-режимов.  
**Ссылка на план:** IMPLEMENTATION_PLAN 3.4.2 (2 секунды recovery при TPS > 19.5).  
**Сложность:** низкая.

## Низкий приоритет / Phase 6

### 6. Тестирование на Linux
**Что:** Запустить сервер на Linux и проверить `LinuxAffinity` + `posix_madvise`.  
**Почему:** Кроссплатформенная гарантия; Linux — основная целевая платформа.  
**Сложность:** только тестирование.

### 7. Совместимость с Terralith / Biomes O' Plenty
**Что:** Протестировать генерацию и загрузку чанков с популярными модами генерации мира.  
**Почему:** Убедиться, что ZeroSeek не ломает модded-генерацию.  
**Сложность:** только тестирование.

### 8. TPS-профилирование с 10+ игроками на элитрах
**Что:** Замерить TPS под нагрузкой, когда много игроков летает на элитрах.  
**Почему:** Проверить основные performance-обещания мода.  
**Сложность:** тестирование + возможные доработки.

### 9. Документация для админов
**Что:** Написать отдельный гайд для администраторов: настройка конфига, совместимость, troubleshooting, ожидаемая производительность.  
**Почему:** README слишком краток для операторов серверов.  
**Сложность:** документация.

### 10. Корректная обработка ошибок прав в affinity
**Что:** Обрабатывать `EPERM` (Linux) и `ERROR_ACCESS_DENIED` (Windows) при попытке привязки affinity без привилегий.  
**Почему:** Не плодить ошибки в ограниченных окружениях.  
**Сложность:** низкая.

## Опционально / Nice to Have

### 11. Оптимизация LRU eviction
**Что:** Заменить O(n) сканирование LRU на ordered linked-структуру; вынести `evictTargetRatio` в конфиг.  
**Почему:** Текущая реализация достаточно быстрая, но O(n) может стать заметной при тысячах открытых регионов.  
**Сложность:** средняя; актуально, если профилирование покажет проблему.

### 12. Метрики / наблюдаемость
**Что:** Добавить команды или логи с метриками: mapped bytes, количество кэшированных регионов, rejected tasks, история TPS-состояний.  
**Почему:** Облегчает настройку и отладку админам.  
**Сложность:** средняя.

### 13. Валидация конфига
**Что:** Проверять значения конфига при загрузке (`maxMappedBytes >= 0`, количество потоков > 0 и т.д.).  
**Почему:** Предотвращает скрытые misconfiguration.  
**Сложность:** низкая.
